# 脉冲：项目结构、第三方接口与币圈概念

这份文档说明三件事：程序接到了哪些外部接口、这些接口里的字段在币圈是什么意思、代码按什么顺序把它们变成扫描、打分、纸面成交和回测。

脉冲是一个模因币研究台。行情来自链上交易所的公开池子，成交只发生在本机的纸面账本里。没有钱包、没有私钥、没有 OKX 或其他中心化交易所的下单接口。

## 第三方接口

整个项目只对接一个外部行情源：[GeckoTerminal 公开 API](https://api.geckoterminal.com/docs/index.html)，基址是 `https://api.geckoterminal.com/api/v2`。不需要 API key。实现在 `lib/gecko.ts`。请求带固定 User-Agent，成功响应在内存里缓存 15 秒。遇到 HTTP 429 会等 0.8 秒再试一次。刷新太密仍会被限流。

页面上的「查看池子」会打开 GeckoTerminal 网站，那是给人看的链接，不是程序调用的接口：

`https://www.geckoterminal.com/{network}/pools/{poolAddress}`

### 1. 趋势池

```
GET /networks/{network}/trending_pools?include=base_token,quote_token,dex&page={1|2}
```

`network` 只允许四条链：`solana`、`base`、`eth`、`bsc`。默认先拉第 1 页，再尝试第 2 页，拼成大约几十个池。搜索框少于 2 个字符时走这个接口。

它回答的问题是：这条链上，最近谁最热闹。热闹不等于该买。后面的过滤和打分会把其中大部分丢掉。

### 2. 搜索池子

```
GET /search/pools?query={关键词}&network={network}
```

搜索框至少 2 个字符时改走这个接口，并且仍然只保留当前选中的那条链。

### 3. 单个池子

```
GET /networks/{network}/pools/{address}?include=base_token,quote_token,dex
```

手动开仓、手动平仓，以及持仓已经不在趋势榜上时的价格更新，都用这个接口拿最新中间价和流动性。

### 4. K 线

```
GET /networks/{network}/pools/{address}/ohlcv/minute?aggregate=5&limit=288&currency=usd
```

只用于回测。`aggregate=5` 表示 5 分钟一根，`limit=288` 大约覆盖一天。返回的每一行是：

`[时间戳, 开, 高, 低, 收, 成交额]`

时间戳若小于 `10^12`，按秒处理并乘成毫秒。接口通常把最新的 K 线放在前面，程序会按时间从旧到新排好。

`include=base_token,quote_token,dex` 会在响应的 `included` 里带回代币符号和 DEX 名称。没有这项时，程序从池子名字（例如 `BONK / SOL`）里拆出两边的符号。

### 程序自己的接口

浏览器不直接打 GeckoTerminal，只打本机的三个路由。这样密钥、缓存和账本都留在服务端。当前没有密钥。

| 路由 | 作用 |
| --- | --- |
| `GET /api/scan?network=&q=` | 拉宇宙，用当前规则打分，按分数从高到低返回 |
| `GET /api/book` | 读纸面账本 |
| `POST /api/book` | `tick` 结算一轮，`arm` 开关自动，`config` 保存规则，`buy` / `sell` 手动开平仓，`reset` 清空账本并保留规则 |
| `POST /api/backtest` | 拉 K 线和当前流动性，跑回测 |

## 接口字段对应的币圈概念

下面这些词都出现在 GeckoTerminal 的池子对象里，或由这些字段算出来。

### 链、代币、池子、DEX

一条链是一套独立账本。Solana、Base、Ethereum、BSC 上的同名币不是同一个合约，余额和交易也不能直接搬过去。

代币合约地址才是身份。符号（比如 BONK）可以撞名。程序用 `baseAddress` 识别「同一只币」。

池子是 DEX 上的一个交易场所，里面同时放着两种资产：要交易的币（base）和用来计价的资产（quote）。池子地址和代币地址不是同一个东西。策略交易的是某个池，不是抽象的「这个币在全市场的价格」。

DEX 是链上的自动交易所。数据里常见的是 PumpSwap、Raydium、Meteora，以及以太坊和 Base 上的各类 Uniswap 池。程序只记录 DEX 名字，不向它们发送交易。

报价资产是池子右边那个币。`BONK / SOL` 里的 SOL 就是报价。程序默认只接受 SOL、WSOL、ETH、WETH、BNB、WBNB、USDC、USDT、USD1。用股票代币或其他小币计价的池子会被拒，因为那种价格里还叠着报价资产自己的涨跌，流动性也更难退出。

### 价格、K 线、成交额

`base_token_price_usd` 是这一刻的美元中间价，来自池子两边储备的比值，再换成美元。它不是某笔真实成交价。纸面买入会在这个价格上再加滑点和手续费。

K 线把一段时间压成开、高、低、收。5 分钟 K 线的「收」是这 5 分钟结束时的价格，不是这 5 分钟里每一笔的价格。回测规定：信号在本根收盘才算数，成交放到下一根的开盘价。这样不会用到这根 K 线还没走完时的信息。

成交额 `volume_usd` 是这段时间里池子的美元成交量。模因币上它可以被来回对倒刷高，所以程序不单独用「量大」当买入理由。

### 流动性、换手、滑点

`reserve_in_usd` 是池子里两边资产按美元加总的储备，界面上叫流动性。它大致表示这个池子能承接多大的单。4 万美元是默认最低线：再薄，卖出时价格会被自己的单砸穿。

换手 = 1 小时成交额 / 流动性。0.55 倍附近分数最高。接近 0 表示没人交易。高到数倍以上，要么是极热，要么是用很少的真实资金刷出来的成交。

恒定乘积是多数这类池子的做市公式：池子里两种资产的数量相乘近似不变。你拿报价资产去买币，币变少、报价资产变多，下一枚币就更贵。买得越多，成交价越偏离下单前的中间价，这个偏离就是滑点。

程序的近似是：池子大致平衡时，报价资产储备 ≈ 流动性的一半。单边冲击 ≈ 下单金额 / 报价储备，再加 30 bps 手续费（1 bp = 0.01%）。单笔默认不超过 400 美元，也不超过流动性的 1.5%。预估成本超过 180 bps，或下单金额达到报价储备的一半，就拒绝这笔成交。卖出用同一套公式从中间价往下扣。若单子大到公式无法成交，纸面强平会按 50% 冲击处理，并在日志里写明。

中心化交易所上的限价单网格不走这个公式。OKX 网格成交的是订单簿上的挂单，成本主要是手续费和买卖价差，不会因为你这一笔占了池子储备的一定比例而自动把价格打歪。

### FDV、市值、池龄

FDV（完全稀释估值）≈ 价格 × 总供应量，包含还没流通的部分。市值通常只乘已流通量。接口里两者都可能缺失或为 0，缺失时程序跳过这项，不把它当成 0。

FDV / 流动性很高，表示价格所对应的估值远大于池子里真正能交易的钱。这种池子价格容易被小单拉动。默认比值超过 120 就拒绝开仓，超过 80 或 150 还会扣分。

池龄来自 `pool_created_at`。默认至少 45 分钟。新建池的前几十分钟里，滑点、合约是否允许卖出、以及内部人抛售都还没充分暴露。没有建池时间的池子也不能开仓。

### 买卖笔数和买卖差

`transactions.h1.buys` 和 `sells` 是 1 小时内的买入笔数和卖出笔数。`buyers` 和 `sellers` 是独立地址数，用来看是不是少数地址在对倒。

买卖差 = `(买笔数 - 卖笔数) / (买笔数 + 卖笔数)`，范围大约从 -1 到 +1。默认至少 +0.04 才允许开仓。分数里还会再看买方地址是否多于卖方地址。

5 分钟、15 分钟、1 小时、6 小时、24 小时的涨跌幅是 `price_change_percentage`，单位是百分数，`-13.5` 表示跌了 13.5%。开仓要求 1 小时涨幅在 2% 到 90%：太弱没有延续，太陡更像已经拉完。动量分数的峰值在大约 +16%，再往上分数下降。5 分钟跌幅达到或超过 8%～10% 会压低分数。

### 纸面交易、止损、移动止盈

纸面账本存在本机 `data/portfolio.json`，不进 git。默认起始资金 10,000 美元。净值 = 现金 + 持仓按卖出冲击折算后的美元价值，所以一开仓净值就会比中间价浮盈略低，因为已经扣了买和未来卖的成本。

止损 14%、止盈 50% 都按成交价算。开仓滑点会先吃掉一部分止损距离。浮盈达到 20% 之后，价格从最高点回撤 12% 就移动止盈。拿满 10 分钟后，分数跌破 40 也会走。最长持有 240 分钟。当天回撤达到 8% 后，已有仓位仍会出场，但不再开新仓。每一轮最多新开 1 只，持仓上限 4 只。

这些百分比都可以在「组合」里改。改完下一轮扫描会用新门槛重新打分。

### 回测和实盘之间还缺的概念

K 线没有买卖笔数，所以回测进场改成：约 1 小时动量落在同一涨幅区间，成交量高于均量 1.7 倍，收盘落在这根 K 线高低点的上半段。出场仍用止损、止盈、移动止盈和持有时间。它是扫描策略的近似，不是同一套分数的逐笔回放。

滑点用回测当时的流动性套到一整天的历史上。池子刚建立时通常更浅，这样算出来的收益偏乐观。

貔貅指合约允许买入、却限制或禁止卖出。公开的价格和成交量看不出这一点。纸面能平仓，不代表链上卖得掉。程序没有做卖出探测，也没有接安全扫描服务。

对倒是同一拨人左右手互买，把成交额和买盘笔数做高。换手极端高、而独立买家很少时，分数会变差，但仅靠这个接口不能证明是对倒。

## 代码怎么分层

```
app/page.tsx                 页面入口
app/api/scan|book|backtest   浏览器能调用的三个接口
components/desk.tsx          顶栏、扫描刷新、结算、四个标签
components/scanner-view.tsx  趋势表、分数拆解、按规则开仓
components/book-view.tsx     净值、持仓、成交、规则表单
components/backtest-view.tsx 回测结果
components/method-view.tsx   界面里的方法说明
lib/gecko.ts                 唯一的外部行情客户端
lib/quant.ts                 过滤、打分、滑点、出场、回测（纯函数，有单测）
lib/portfolio.ts             纸面账本的读写和一轮结算
lib/types.ts                 池子、规则、持仓、回测的数据结构
lib/networks.ts              四条链和池子地址格式
data/portfolio.json          运行后才出现的账本，不提交
```

`lib/quant.ts` 不访问网络，也不读写文件。`lib/quant.test.ts` 用假池子和假 K 线锁住滑点公式、开仓条件和「信号在下一根开盘才成交」。

界面组件只负责展示和发请求。规则的数字以服务端账本里的 `config` 为准。

## 三条主路径

### 扫描

1. 界面按当前链和搜索词请求 `/api/scan`。
2. 服务端读账本里的规则，再向 GeckoTerminal 要趋势池或搜索结果。
3. 同一条链、同一个 base 代币若有多个池，只留流动性更深的那个。
4. `evaluatePool` 先做硬过滤，再算四项分数和扣分，得到 `enter`、`watch` 或 `reject`。
5. 界面按分数排序。点一行可以看到每一条门槛为什么过或没过。

`reject` 是结构不合格，例如池子太薄、太新、报价不对。`watch` 是结构合格，但涨幅、买卖差或分数还没到开仓线。`enter` 是全部条件都过。

### 结算一轮

自动开仓默认关闭。关闭时，结算只更新已有持仓的价格，并检查出场。打开后，还会从当前这条链的趋势池里，选分数最高且信号为 `enter` 的一只，尝试开一笔。

出场优先于开仓。顺序是止损、止盈、移动止盈，然后才是分数跌破和持有超时。开仓前再检查：今天回撤是否已经到上限、持仓是否已满、仓位是否至少 25 美元、滑点是否在上限内。

### 回测

界面把当前选中池子的链和池子地址交给 `/api/backtest`。服务端同时拉该池的最新快照和约一天的 5 分钟 K 线，用账本里的止损止盈参数跑 `runBacktest`。同一时间只持有一笔。若结束时仍有持仓，净值按卖出冲击计入。

## 这个项目没有对接的东西

- OKX、币安或其他中心化交易所的行情和网格、定投、信号机器人接口。
- 钱包、私钥、RPC 节点、DEX 聚合器和链上发交易。
- Twitter、Telegram 等社媒热度。
- 貔貅或合约权限扫描。

若以后要和 OKX 网格放在一起比较，需要另接交易所 K 线和订单接口，并单独定义网格的区间、档距和库存规则。那些不在当前代码里。
